# ZTHL Aegis v0.11.1 — 发布说明

> 本版**只动文档面**：运行时行为、命令集合、状态文件格式与发布流程都没有变化。
> 变的是一件事——**机制必须有自己的正本，而且正本里的事实由代码生成、由闸守着**。
>
> 区间 `v0.10.0..v0.11.1` 共 8 个提交。

---

## 一、这个版本想解决什么问题

v0.10.0 之前的 260 个提交里，工作目录池、合并前置闸、审计生命周期、发布管线这四个机制
都只活在代码里：读者只能读源码，文档里没有一份能称为「正本」的东西。事后补写的四份文档
如果继续靠人维护，机制一改就会静默滞后——这正是当初把统计数字收进自动生成事实块的原因。

v0.11.1 做三件事：

1. **补齐四份机制正本**，每份带一块**自动生成**的机制面事实表；
2. **发版预检加第 16 道闸**：新机制只进代码、不进文档，将直接被拦下；
3. **发布说明三节自动填充**（性能红利 / 架构进化 / 安全哲学），并为安全主张加代码锚点机检。

## 三、详细变更

### 3.1 机制登记表与正本（新增）

新增 `references/mechanism-registry.json`，作为「机制 → 正本文档 → 入口脚本 → 测试 → 校验命令」
的单一事实源。当前登记四个机制：

- **合并前置闸** → `references/merge-gate.md`（4 个入口脚本）
- **工作目录池与路由** → `references/worktree-pool.md`（4 个入口脚本）
- **审计生命周期** → `references/audit-lifecycle.md`（3 个入口脚本）
- **发布管线** → `references/release-pipeline.md`（6 个入口脚本）

每份正本里有一块 `GK-MECH` 事实表：入口脚本清单、公开函数数、CLI 入口、测试文件、校验命令。
内容全部从活代码派生，由新增的 `scripts/gk_mechanism_docs.py --write` 生成；`--check` 只比对，
不一致就报错并提示重跑生成器。手改这块内容会被闸打回。

### 3.2 发版预检：15 项 → 16 项（新增 `mechanism_docs`）

新闸查两件事：

1. **登记即闭环**：登记机制的正本事实表必须与活代码一致（漂移、缺文档、缺入口脚本、缺测试、
   CLI 入口未注册，任一命中即 FAIL）；
2. **新增即登记**：`上一版..HEAD` 新增的机制脚本必须落在某个机制的入口清单里，否则要么补正本，
   要么在登记表的豁免区写明理由——**没有理由的豁免本身判红**。

口径与既有纪律一致：只有 FAIL 判红，WARN 放行；覆盖度区间**只在私仓生效**（判据 = `docs/`
是否随包），公开镜像是单提交快照，拿它算新增面会把整棵树都算成新增。

### 3.3 发布说明：三节自动填充 + 安全锚点机检（新增）

`gk_release_notes.py generate` 现在默认产出三节，数据源全部可复算：

| 小节 | 取数面 | 纪律 |
|:--|:--|:--|
| 性能红利 | 性能基线的提交/场景/过期阈值 + 本版是否触碰性能面机制模块 | 没动性能面就写「无变化」，不吹提升 |
| 架构进化 | 机制登记表命中的机制 + 区间内新增的文档/脚本面 | 没动机制入口就写「无机制面演进」 |
| 安全哲学 | 登记表里的安全不变式 + 逐条代码锚点验证 | 锚点失效显式标红 |

同时新增 **C5 机检**：说明里出现某条安全主张时，它的代码锚点必须仍然存在。
动机很直接——写成口号的安全承诺，过两版就没人能证明它还在。

## 四、兼容性与升级

- **命令不变**：既有子命令与参数全部保留；本版没有新增或删除 CLI 命令。
- **状态文件不变**：没有新增字段，旧状态可直接读。
- **文档位置**：新增四份正本，原有阶段文档保留为流程视角，并在文首指向对应正本。
- **新增只读清单**：`references/mechanism-registry.json` 随包发布，可用于第三方核对机制面。
- **预检更严**：新机制不登记会被拦；这是有意的收紧，处置方式见 3.2。

## 七、能力边界（不要误读）

1. **覆盖判据只查新增**：新闸拦的是「本版新增的机制脚本」，不是把仓内全部脚本一次性回填正本；
   存量脚本的正本化按主线节奏推进。
2. **安全不变式是登记面，不是穷举**：七条不变式覆盖主干写入、票据、受保护区、导出、推送、
   预检纪律与计数口径；新增不变式要先在登记表登记，才能进入说明。
3. **事实表只证明「文档与代码一致」**：它不判断机制设计好坏，也不替代测试。
