# Research 408 — 计算机 408 四轴优化分析

**定位**：`ECO-RESEARCH` 的可选分析帧。默认 **auto**：程序按任务文本/阶段判断是否值得走 408；
本帧把同一个研究问题改写成 **408 四轴 + 八段报告**，专门回答「从计算机系统底层看，
这个优化该怎么做、代价是什么、怎么验证」。

**启用 / 覆盖**：

```bash
GK_RESEARCH_FRAME=auto     # 默认；程序自动判定
GK_RESEARCH_FRAME=408      # 强制开启
GK_RESEARCH_FRAME=generic  # 强制关闭
```

帧只影响分析产物，**不参与任何 gate**：不开启、判定失败、没有输出，都不阻塞 advance / EDIT / 质询。

## 自动判定（auto）

判定只看任务文本、目标、计划标题/片段、阶段与项目类型，确定性、0 API：

| 信号 | 判定 |
|:--|:--|
| 只有系统信号（state/storage/索引/并发/锁/崩溃/写放大/缓存/OS/网络/CI/重构…） | `408` |
| 只有创作信号（文案/艺术/海报/营销/翻译/小说/剧本…） | `generic` |
| 两类都有 | 创作信号数 ≥ 系统信号数 → `generic`；否则 `408` |
| 无信号 | `standing` / `ECO-*` / `RED-*` / `AUDIT-*` → `408`（自维护默认）；其余 `generic` |

显式 `408` / `generic` 永远优先。判定结果落在 `advance` 输出的
`research_frame` 字段（`{frame, reason, auto, blocking:false, signals}`），供调用方决定是否展开；
不消费该字段的路径照常运行。

## 一、四轴

| 轴 | 必答问题 | 典型产物 |
|:--|:--|:--|
| **数据结构** | 用 DAG / LSM / B+ 树 / 堆 / 外排中的哪一种？不变量是什么？时间/空间复杂度？ | 结构图、复杂度表、不变量清单 |
| **计算机组成** | 内存层次与缓存局部性如何？写放大是多少？fsync / 原子替换 / 对齐 / 页缓存怎么参与？ | 写路径图、写放大估算、I/O 次数 |
| **操作系统** | 进程/线程/协程怎么分？锁粒度、可重入、死锁与超时？虚拟内存、文件系统、崩溃一致性？ | 锁序、崩溃恢复点、锁竞争预算 |
| **计算机网络** | 是否跨进程/跨机？重试、幂等、超时、一致性、共识？单机场景明确写 N/A。 | 失败重试表、幂等键、一致性级别 |

> 408 的“计算机网络”轴不是凑数：只要状态/索引/锁跨了进程或机器，就必须回答重复写、乱序、
> 半失败和脑裂；单机单进程则显式标 N/A，避免假装分析过。

## 二、八段报告模板

1. **负载模型**：读写比例、单条大小、并发度、峰值/稳态、可接受延迟。
2. **数据结构**：选型、不变量、最坏/均摊复杂度、替代方案与放弃理由。
3. **内存与写路径**：缓存层次、写放大、fsync/rename、批量/合并、冷热分层。
4. **并发与崩溃一致性**：锁/无锁、提交顺序、崩溃点、恢复流程、幂等。
5. **复杂度预算**：时间/空间上限、状态体积、GC/压缩成本、最坏情况。
6. **失败模式**：半写、丢更新、重复写、锁超时、磁盘满、版本漂移、回滚失败。
7. **实验与验证**：基准、故障注入、崩溃恢复、并发压测、指标与阈值。
8. **408 结论**：推荐方案、否决方案、剩余风险、下一步可验证动作。

## 三、纪律

- **先建模再选型**：没有负载模型的结构选型一律视为未完成。
- **量化写放大**：至少给出「一次逻辑写 → 多少次物理写 / 多少字节」。
- **崩溃点是显式的**：每个持久化步骤写清楚“此步崩溃后读到什么”。
- **不能把缓存当事实源**：热索引/缓存可以丢，事实源必须可重建。
- **N/A 要写出来**：不适用的轴明确标 N/A，不省略。
- **结论必须可证伪**：每条建议对应一个实验/指标/阈值。

## 四、非目标

- 不替代 `plan-refinement` 的 F1-F7 质询。
- 不引入外部依赖或运行时引擎；它是一份分析协议 + hint。
- 不因为启用了 408 帧就跳过 `research_prelude` 的证据清单。
